# Data Schema Reference

This file documents the data files excluded from git (715MB total in `data/`). Use this to understand schemas and regenerate from scratch.

## Parquet Files

### `data/backdrop_games.parquet` (~61K rows)

All Steam games released 2023-01-01 to 2026-03-18. One row per game.

| Column | Type | Description |
|--------|------|-------------|
| steamId | str | Steam app ID (string) |
| name | str | Game title |
| price | float | Current price USD |
| reviews | int | Review count |
| reviewScore | float | Review score |
| followers | int | Steam follower count (true API data) |
| wishlists | int | Wishlist count (Gamalytic estimate) |
| copiesSold | int | Copies sold (estimate) |
| revenue | float | Revenue USD (estimate) |
| totalRevenue | float | Total revenue USD (estimate) |
| tags | list[str] | Steam store tags |
| genres | list[str] | Steam genres |
| features | list[str] | Steam features |
| developers | list[str] | Developer names |
| publishers | list[str] | Publisher names |
| firstReleaseDate | datetime | First release date (converted from epoch ms) |
| earlyAccess | bool | Early Access flag |
| earlyAccessExitDate | datetime | EA exit date (converted from epoch ms) |

Generated by: `python src/01_collect_backdrop.py`

| Column | Type | Description |

| group | str | "success" or "control" |
| launch_date | datetime | First release date |
| price_at_launch | float | Price at launch |
| early_access | bool | Early Access flag |
| days_on_steam_pre_launch | int | Days between page creation and launch |
| wishlists_at_launch | float | Wishlist count at launch (estimate) |
| followers_at_launch | float | Follower count at launch (true) |
| reviews_at_launch | float | Review count at launch |
| wishlist_velocity_30d | float | Wishlists/day, 30d pre-launch window (None if insufficient data) |
| wishlist_velocity_90d | float | Wishlists/day, 90d pre-launch window |
| wishlist_velocity_180d | float | Wishlists/day, 180d pre-launch window |
| follower_velocity_30d | float | Followers/day, 30d pre-launch window |
| follower_velocity_90d | float | Followers/day, 90d pre-launch window |
| follower_velocity_180d | float | Followers/day, 180d pre-launch window |
| tags | list[str] | Steam tags |
| genres | list[str] | Steam genres |
| tag_count | int | Number of tags |
| genre_count | int | Number of genres |
| first_month_copies | float | Copies sold in first 30 days |
| first_month_revenue | float | Revenue in first 30 days |
| prior_game_count | int | Developer's prior games (from backdrop) |
| prior_avg_revenue | float | Developer's prior avg revenue |

Generated by: `python src/04_build_analysis_set.py`

### `data/forward_observations.parquet` (~330 games, many rows per game)

Time-series observations for success+control games with rolling growth rates.

| Column | Type | Description |
|--------|------|-------------|
| steamId | str | Steam app ID |
| group | str | "success" or "control" |
| metric | str | "followers" or "wishlists" |
| date | datetime | Observation date |
| days_to_launch | int | Days until launch (positive = before launch) |
| days_since_creation | int | Days since Steam page creation |
| total | float | Cumulative metric value at this date |
| daily_growth_7d | float | 7-day rolling mean of daily growth rate |
| daily_growth_30d | float | 30-day rolling mean of daily growth rate |
| onset_artifact | bool | True if first history entry had >100 followers (mid-life tracking start) |

Generated by: `python src/06_forward_analysis.py`

## JSON Files

### `data/histories/*.json` (~4,872 files, ~700MB)

One JSON file per game, named `{steamId}.json`. Raw Gamalytic API response from `/game/{id}` with `include_pre_release_history=true`.

Top-level structure:
```json
{
  "steamId": 1234567,
  "name": "Game Name",
  "price": 29.99,
  "tags": ["Action", "RPG"],
  "genres": ["Action", "Adventure"],
  "features": ["Single-player", "Co-op"],
  "developers": ["Studio Name"],
  "publishers": ["Publisher Name"],
  "copiesSold": 100000,
  "revenue": 2500000,
  "totalRevenue": 3000000,
  "wishlists": 50000,
  "followers": 25000,
  "reviews": 5000,
  "reviewScore": 85,
  "firstReleaseDate": 1700000000000,
  "releaseDate": 1700000000000,
  "earlyAccess": false,
  "earlyAccessExitDate": null,
  "EAReleaseDate": null,
  "history": [
    {
      "timeStamp": 1690000000000,
      "reviews": 0,
      "price": 29.99,
      "score": 0,
      "players": 0,
      "avgPlaytime": 0,
      "sales": 0,
      "revenue": 0,
      "followers": 100,
      "wishlists": 500
    }
  ]
}
```

Key notes:
- Timestamps are **epoch milliseconds** (not seconds)
- History entries use `timeStamp` key (camelCase, not `date`)
- Follower counts are true Steam API data; wishlists/revenue/sales are Gamalytic estimates
- ~3,819 of 4,872 files have meaningful pre-launch data (>7 days before release)

### `data/backdrop_progress.json`

Resume checkpoint for `01_collect_backdrop.py`. Contains `pages_collected` (list of page indices) and `all_games` (accumulated raw API responses). Not needed for analysis; only used for resuming interrupted collection.

## Config Files

### `config/success_games.json`

Hand-curated list of 30 "standout" Steam games. Array of objects:
```json
[
  {"steamId": "1808500", "name": "ARC Raiders", "notes": "Co-op PvE extraction shooter by Embark Studios"},
  ...
]
```

### `config/control_group.json`

Maps each success game's steamId to ~10 matched control game IDs. Matching criteria: Jaccard tag similarity 60%, release date proximity 20%, price similarity 20%.
```json
{
  "1808500": ["2523720", "3065800", "2373990", ...],
  "3527290": ["3645890", "2835530", ...],
  ...
}
```

Generated interactively by: `python src/02_match_control_group.py`

### `config/control_candidates.txt`, `config/control_candidates_wave2.txt`

Intermediate outputs from the control matching process. Lists of candidate control game IDs considered during matching.

## Regeneration Pipeline

Run scripts sequentially from project root. Requires `.env` with `GAMALYTIC_API_KEY` (Pro tier).

```
Step 01  →  backdrop_games.parquet          (API: ~62 paginated list calls)
Step 02  →  control_group.json              (interactive, uses backdrop data)
Step 03  →  histories/*.json + timeseries   (API: ~330 detail calls, resume-safe)
Step 03b →  histories/*.json extended       (API: ~4,500 stratified sample calls)
Step 03c →  histories/*.json re-fetched     (API: re-fetch with pre_release flag)
Step 04  →  analysis_features.parquet       (local compute from histories)
Step 06  →  forward_observations.parquet    (local compute from histories)
Step 10  →  output/report.html              (local, reads all data)
```

Steps 01, 03, 03b, 03c make Gamalytic API calls and are resume-safe (skip already-fetched items). Step 02 is interactive. Steps 04, 06, 10 are purely local computation.

**Critical**: Step 03b originally omitted `include_pre_release_history=True`. Step 03c fixes this by re-fetching backdrop games that lacked pre-launch data. Always pass this flag when calling `get_game_details()`.
